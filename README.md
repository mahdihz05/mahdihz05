# Mahdi Hosseinzadeh

Software engineer and entrepreneur working on web platforms, content systems, and product automation. I also study Physics and am interested in scientific computing.

## Engineering focus

- **Content operations:** AI-assisted planning and drafting, human approval, and publishing workflows—with editorial planning kept separate from the delivery queue.
- **Reusable CMS engineering:** structured content, localization, publishing permissions, technical SEO, and explicit boundaries between authoring, APIs, and presentation.
- **Web applications:** Python/Django backends, JavaScript/TypeScript interfaces, and Persian right-to-left experiences.

## Where to start

- **Product automation:** read the [workflow and approval boundary](https://github.com/mahdihz05/abrit-content-platform-showcase#workflow-and-approval-boundary); treat it as a narrative, not executable evidence.
- **Reusable CMS code:** follow the [Payload architecture](https://github.com/mahdihz05/payload-CMS/blob/main/docs/ARCHITECTURE.md) and [CI definition](https://github.com/mahdihz05/payload-CMS/blob/main/.github/workflows/starter-ci.yml).
- **Headless CMS tradeoffs:** review [Visiona architecture decisions](https://github.com/mahdihz05/CMS/blob/main/docs/architecture-decisions.md) and its README maturity notes.

## How to read this portfolio

Code, documentation, and configured checks are different kinds of evidence. A workflow file describes intended checks; run results apply only to the commit they tested. Each README explains project-specific limitations. This profile does not certify production readiness, security, coverage, or mastery of every technology listed.

I use AI coding tools for implementation support, review, and documentation; their involvement does not replace engineering review. My interests include software architecture, agent-assisted engineering, automation, and the intersection of Physics and programming.
